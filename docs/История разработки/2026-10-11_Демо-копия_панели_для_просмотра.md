# 11.10.2026 — Демо-копия панели для просмотра другим пользователем

## Задача

Собрать копию веб-приложения NeroAI (Центр запуска + редактор карт), которую можно
отправить другому человеку: он открывает её у себя и смотрит интерфейс без Arma,
моста, LLM и Node.js. Уточнение пользователя: карты — в оригинальном виде.

## Результат

- Архив: `dist/share-demo/NeroAI-Control-Center-Demo.zip` (≈1,55 ГБ, 15 405 файлов).
- Папка: `dist/share-demo/NeroAI-Control-Center-Demo/` (≈1,57 ГБ).
- Открытие: распаковать → двойной щелчок по `NeroAI Control Center.html`.
  Внутри `README_RU.txt` для получателя.

Карты в оригинале, как их отдаёт сама панель: 22 обзора (8K, где он собран),
15 356 подробных спутниковых фрагментов и 22 векторных слоя улиц/зданий.
Не включены только `source.json` (манифесты сборки) и `overview.jpg` там, где есть 8K —
панель их не показывает.

## Как устроено

`tools/build-share-demo.js` (только читает проект, пишет в `dist/share-demo/`):

1. Снимок GET-данных панели через её же модули: `core.publicState`, каталог техники
   и фракций, карты с метаданными фона, сценарии редактора, пресеты карт, значения
   «сбросить по умолчанию», список моделей по сохранённым пресетам.
2. Обезличивание: адреса LLM-узлов → `http://llm-node-N.local:1234/v1` (локальный
   `127.0.0.1` оставлен), профиль Arma → `Player`, удалены `modPath`, `sourcePbo`,
   пути модов и ошибки сканера. Ключей API нет и в исходном `publicState`.
   Сборка **останавливается**, если в снимке или HTML найден IP, путь к диску,
   папка пользователя, имя профиля или ключ.
3. `index.html` и `designer.html` копируются с точечными заменами (каждая проверяется
   по числу вхождений — при изменении панели сборка явно упадёт):
   подключение `demo/demo-data.js` + `demo/demo-shim.js`, ссылки `/designer` →
   `designer.html`, фон `/map-background/` → `maps/<id>.jpg`, фрагменты
   `/map-tile/` → `maps/<id>/tiles/x_y.jpg`, проверка `origin` в `postMessage`
   (под `file://` origin непрозрачный).
4. `tools/share-demo/demo-shim.js` подменяет `fetch('/api/…')`: чтение — из снимка,
   сохранение настроек/пресетов/карт — в `sessionStorage` вкладки (с ревизиями, как
   на сервере). Запуск Arma, окно журнала, сборка фона карты, импорт съёмки и загрузка
   изображения отвечают «В демо-копии недоступно…». Векторные слои грузятся через
   `<script>` (`demo/vector/<id>.js`), потому что `fetch` файлов под `file://` запрещён.
5. Сверху панели — плашка «Демо-копия … снимок <дата>».

Облегчённый вариант (уменьшенные обзоры без фрагментов, ≈десятки МБ):
`node tools/build-share-demo.js --width 3072`.

## Проверка

- HTTP-режим (временный `python -m http.server`) во встроенном браузере: панель,
  пресеты, «Сохранить настройки» с проверкой после записи, «Проверить модели»,
  отказ запуска, редактор карт, приближение — фрагменты 200 OK, улицы и здания,
  сохранение карты и нового пресета карты, сообщение редактора в панель. Консоль без ошибок.
- Режим двойного щелчка (`file://`) в фоновом Chrome с отдельным профилем, на копии,
  распакованной из готового ZIP: обзор 8192 px, фрагменты 480 px, вектор, сохранение
  карты, сообщение «Карта … выбрана для игры» в панели, консоль без ошибок.
  Повторный поиск личных данных по распакованной копии — чисто.

## Ограничения

- Под `file://` панель и встроенный редактор не делят `sessionStorage`: правка карты
  в редакторе не меняет краткую сводку на вкладке запуска до сохранения настроек.
  Внутри каждого окна всё согласовано.
- Изменения живут до закрытия вкладки; на диск ничего не пишется.
- Строка качества фона показывает данные оригинала («Обзор 8K», «2 м/пиксель»).
- Сборка удаляет старую папку копии: перед повторной сборкой закройте всё, что держит
  её открытой (на Windows Node 24 при этом падает с кодом 0xC0000409).
