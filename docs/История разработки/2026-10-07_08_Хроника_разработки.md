## Как устроена система (кратко)

- **Мод (PBO `@NeroAI_Warlords\addons\nerowl.pbo`)** — SQF внутри Arma: снимок обстановки группы → очередь INIDBI2 → ответ → исполнение приказов (`executeMacro` → `vehicleTactics`/`vehicleRoute`/покупки/авиация). Часть родных файлов Warlords переопределяется; они **генерируются** из оригиналов BI скриптами `tools/adapt-*.js` — править нужно адаптеры, не сгенерированные файлы.
- **Мост (`bridge/`, Node)** — читает очередь, собирает запрос к LLM (LM Studio), проверяет ответ по белому списку и привязке к координатам, пишет ответ обратно.
- **Панель (`control-center/`, http://127.0.0.1:18775)** — выбор карты/моделей/параметров, генерация runtime-конфига моста, проверка и установка кандидата PBO, запуск моста и Arma.

## Сквозные правила, выученные по ходу

1. Родные файлы Warlords генерируются адаптерами — правка сгенерированного файла затирается.
2. Панель запускает пользователь своим ярлыком; после правок `control-center/core.js` — перезапуск панели; перед сохранением в панели — обновить страницу.
3. Тесты гонять последовательно (`--test-concurrency=1`): параллельно один тест мешает другому через общую папку миссии.
4. После любой правки `addons/NeroAI3` — пересобрать и проверить кандидат, иначе панель откажет при установке.
5. Пути с обратными слэшами в JSON не править через оболочку (съедаются) — только редактором или скриптом без ручных слэшей.
6. Проверка без движка — не приёмка: всё SQF подтверждается только свежим RPT.
