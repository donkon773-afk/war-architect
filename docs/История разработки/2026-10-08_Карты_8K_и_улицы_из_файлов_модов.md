# Детальные карты для редактора: обзор 8K и улицы из файлов модов — 8 октября 2026

## Запрос

«Используя файлы карт из модов, сформируй детальные карты для отображения в формате 8K… чтобы можно было просматривать каждые улочки без замыленности».

## Почему простое «увеличить до 8K» не работает

Спутниковый фон редактора уже собирался из текстур карт (`s_*_lco.paa`): у Australia это 1849 фрагментов по 2 м/пиксель, у Altis — 1 м/пиксель. Это **предел исходных данных**: в текстуре улица шириной 6–10 м — 3–10 пикселей. Растягивание до 8K или 0,2 м/пиксель только размывает. Чёткость дают только **геометрия** улиц и зданий, которую можно рисовать на любом увеличении.

## Что сделано

### 1. Чтение файла карты WRP прямо из PBO мода (`tools/map-assets/read-wrp.js`)
- Разбор OPRW v20–25: заголовок, квадродеревья, LZO-сжатые массивы (свой LZO1X-распаковщик, который сообщает, сколько прочитано), высоты, материалы, 2412 моделей, сущности, **дорожная сеть** (31 911 участков на Australia; размер блока совпадает байт в байт), **2 290 126 объектов** с положением и поворотом.
- **MapInfo** — то, из чего игра рисует свою карту: дома (контур 4 угла), постройки, стены и заборы, дорожные полосы, ЖД, ЛЭП, деревья. Размеры записей установлены на Australia (31 312 465 байт до последнего байта), типы 41–43 — на Altis/Chernarus/Takistan. **Каждая из 1,1 млн записей сопоставлена со своим объектом по ID** (расхождение < 30 м — 100 %). Неизвестный тип записи — ошибка, а не угаданная карта.

### 2. Дороги карт Terrain Builder (`tools/map-assets/read-roads.js`)
- На картах Arma 3 и CUP 2.x дороги строятся движком из `data/roads/roads.shp` + `roads.dbf` (ID) + `roadslib.cfg` (ширина, класс): читаются из PBO карты или `map_*_data.pbo` игры; сдвиг Terrain Builder по X (200 000) определяется автоматически. Altis — 731 км, Tanoa — 403, Chernarus — 323, Takistan — 160.

### 3. Векторный слой (`tools/map-assets/build-vector-map.js`) → `control-center/data/map-tiles/<карта>/vector.json`
Слои: магистрали / дороги / грунтовки (полосы из MapInfo), линии дорог из шейп-файла с реальной шириной, дома, прочие постройки, стены и заборы, ЖД, ЛЭП, ориентиры. Координаты — целые дециметры. Размер 0,2–6,8 МБ (сжатым в браузер — примерно втрое меньше), сборка 2–10 с на карту.

### 4. Обзор 8K (`tools/map-assets/render-vector.py overview`) → `overview8k.jpg`
8192×8192: спутник + дороги реальной ширины + контуры зданий. Australia — 5 м/пиксель, ~8 с сборки.

### 5. Редактор
- Сервер отдаёт `overview8k.jpg` вместо 4K-обзора и `/map-vector/<карта>.json` (gzip, кэш по времени файла).
- При приближении (кадр ≤ 8 км) редактор рисует улицы и здания векторами: дороги — линиями **в настоящую ширину в метрах**, дома/стены — полигонами; индекс по ячейкам 256 м, один путь SVG на слой. Резко на любом увеличении. Переключатель «Улицы и здания» на карте и флажок во вкладке «Фон карты».
- Кнопка «Собрать фон из файлов» теперь сама строит векторный слой и обзор 8K.
- Скорость перерисовки: 4–33 мс (Altis, центр Australia, кадры 150 м – 8 км).

## Проверка

- Проверочные рендеры: Дарвин (Australia) 0,4 м/пиксель, Кавала (Altis) 0,5 м/пиксель — улицы, кварталы, отдельные дома и заборы участков; обзор 8K Дарвина с аэродромом.
- Живой браузер (временный экземпляр панели на свободном порту; рабочие экземпляры пользователя не трогались): Altis и Australia, векторы загружаются (Altis 2 МБ сжатым), подпись «Обзор 8K · улицы и здания из файла карты».
- Тесты: `tests/map-8k-vector.test.js` 4/4 (MapInfo, шейп-файл, DBF, roadslib, маршрут, редактор). Полный набор: те же 20 старых падений.

## Ограничения

- Спутник под векторами остаётся с исходным разрешением мода (1–2 м/пиксель) — «без замыленности» обеспечивают векторы, не спутник.
- Деревья и кусты (сотни тысяч точек) в слой не включены — их видно на спутнике.
- Новые карты: «Собрать фон из файлов» в редакторе делает всё сразу; массово — `node tools/map-assets/build-all-vector-maps.js`.
