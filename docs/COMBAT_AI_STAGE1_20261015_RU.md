## Причины и результат

Последняя Sanagasta-сессия содержала повторные ASSAULT малочисленным группам. В исходниках подтвердились два перехода: последняя слабая группа продолжает атаку, а истечение времени сбора разрешает штурм без готовых партнёров. Оба перехода изменены.

- Готовность обычной пехоты: по умолчанию не менее 6 боеспособных и 60% исходного состава. Учитываются сознание, возможность двигаться, наличие подходящих магазинов с патронами и подавление. Группа с 1–3 бойцами может защищаться, но не начинает автономную зачистку.
- Экипажи отделены от пехоты по фактическим местам, а не только численности. У боевой машины должны быть пригодный водитель, действующее оружие с боекомплектом и подвижность. Взвод из нескольких экипажей также распознаётся.
- При потере готовности продолжающийся автономный штурм прерывается. При изменении назначения старый штурм также останавливается до обработки нового плана. Прямой приказ игрока сохраняет приоритет.
- Операция имеет состояния PREPARE, RECON, ASSAULT, REASSESS, REINFORCE, CONSOLIDATE. Истечение времени вызывает пересмотр; не отменяет требования к готовности. Если доступны две штурмовые группы, нужны обе; для большего числа требуется примерно половина, максимум три.
- Подтверждённая бронетехника требует подходящей ПТ-поддержки поблизости. Пустой гранатомёт, ПЗРК, дымовой боекомплект и произвольная вооружённая машина не дают такой способности. Лёгкая и тяжёлая броня проверяются раздельно. Большой урон фугасного снаряда сам по себе не считается тяжёлой ПТ-способностью.
- При известном численном превосходстве противника над собранной пехотой более чем в 1,25 раза операция требует усиления. Это начальная эвристика численности, не полная модель огневой мощи.
- Повторные наблюдения движущегося противника объединяются по netId; одно обнаруженное подразделение не превращается в несколько защитников из-за смены координат.
- Подкрепление выбирается по требуемой способности и состоянию. Обороняющиеся/закрепляющиеся группы, занятые логистикой, авиаэкипажи и группы под приказом игрока защищены от этого выбора. Малый ПТ-расчёт допустим для ПТ-задачи, но два обычных бойца не считаются полноценным усилением.
- Назначенная подмога получает окно выполнения 180 с. Неудачный автоматический запрос тоже получает паузу, исключая повторный поиск каждые несколько секунд.
- Пехотным группам назначаются устойчивые разные точки зачистки, до семи базовых участков. Экипажи боевых машин получают огневую/ПТ-роль, вместо пехотного CQB/HUNT.
- После обнаружения нового захвата назначается группа закрепления на 120 с, если есть доступная группа; уже назначенные защитники других угрожаемых секторов сохраняют задачу. Начальное владение секторами не считается новым захватом.
- В тактическом режиме пересмотр не подавляется экономией LLM-запросов. Очередь планирования отдаёт приоритет отмене опасного штурма и новым назначениям, затем давно не обработанным группам. Бюджет — 4 плана за проход; плановый интервал — 15 с. Фактическая задержка зависит от цикла сервера и числа групп.

## Настройки

Значения по умолчанию находятся в `addons/NeroAI3/functions/bootstrap/fn_preInit.sqf`:

| Переменная | Значение | Назначение |
|---|---:|---|
| NeroAI_rulesMinAssaultStrength | 6 | Минимум боеспособной пехоты |
| NeroAI_rulesMinAssaultRatio | 0.6 | Доля от исходного состава |
| NeroAI_rulesConsolidateSeconds | 120 | Окно закрепления |
| NeroAI_rulesPlanIntervalSeconds | 15 | Плановый пересмотр |
| NeroAI_rulesMaxParallelPlans | 4 | Бюджет планов за проход |
| NeroAI_rulesAmmoTierOverrides | HashMap | Поправки для особых боеприпасов модов |

Для малой специальной группы после инициализации можно задать её собственный минимум:

```sqf
_group setVariable ["NeroAI_rulesMinAssaultStrength",4];
```

Пример поправки на конкретный класс магазина, после проверки его реального назначения:

```sqf
NeroAI_rulesAmmoTierOverrides set ["ExactMagazineClass",2];
```

Уровень 0 — не ПТ, 1 — лёгкая броня, 2 — тяжёлая. Это оценка способности, а не гарантия пробития. Эти параметры пока не добавлены в редактор фракционных пресетов.

## Следующий игровой рубеж

Нужна отдельная испытательная миссия в режиме тактического ИИ, с проверенным включением именно кандидата. Не подключать одновременно старый и новый экземпляры одного аддона.

1. Целые отделения: выход на рубеж, сбор минимум двух при наличии двух, затем штурм; одна здоровая группа допускается, когда другой нет и нет блокирующей известной угрозы.
2. Потери до 1–3 бойцов во время CQB: прекращение старой зачистки, самооборона/отход, без повторного ASSAULT. Проверить с LAMBS и без него.
3. Танковый контакт: пустой гранатомёт, только ПЗРК/пулемёт, исправное ПТ-оружие с ракетой. Проверить выбранного помощника, его действительное прибытие и отсутствие снятия последнего защитника.
4. Экипаж одной машины и взвод из нескольких машин: огневая роль, без пехотной зачистки; при утрате боекомплекта/мобильности повторная оценка.
5. Захват сектора: назначение закрепления и отсутствие немедленного ухода всех доступных групп на следующую цель.
6. Новый приказ игрока во время сбора, отмены штурма и работы подмоги: автономия не отменяет его.
7. Большое число групп: нет постоянного обслуживания только первых записей; оценить ServerFPS и фактическую задержку решений.

Искать в свежем RPT `OPERATION WEST/EAST PREPARE/RECON/ASSAULT/REASSESS/REINFORCE/CONSOLIDATE`, `RULES ... -> REGROUP/SELF_DEFEND/FIRE_SUPPORT`, затем сверять с действиями в игре. Сообщение о принятом приказе само по себе не подтверждает движение, огонь или захват.

Остаются ограничения: боекомплект считается пригодным при наличии патронов, без расчёта времени до истощения; модовые типы пробития требуют калибровки; участки CQB пока не ведут реестр очищенных зданий; огневой рубеж машины пока геометрический, без анализа рельефа/линии огня. Текущая регистрация групп остаётся серверной, HC/locality вынесены в этап 6.
