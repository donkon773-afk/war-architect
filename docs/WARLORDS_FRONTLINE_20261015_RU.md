# Warlords: отмена отрезанного захвата и контратака при осаде базы

Дата: 15.10.2026. Проект: `C:\Users\Admin\Desktop\ИИ\NeroAI_Warlords_DualLLM`. Изменения сделаны в исходниках и отдельной проверенной сборке; активная игровая сессия не изменена.

## Причины и поведение

Исследован установленный игровой `H:\SteamLibrary\steamapps\common\Arma 3\Addons\functions_f_warlords.pbo`, функции WLSectorListing, WLSectorHandleServer, WLSectorSelectionHandleServer, WLAICore и WLAIPathSegmentation. Нативное перечисление доступных секторов уже строит связную цепь от своей базы, но активная цель не отменяется при потере предыдущего звена. Триггеры захвата допускают исторически завоёванные сектора независимо от текущей связности. Поэтому одного пересчёта доступных целей недостаточно.

Вторая причина: WLAICore имеет девять переходов «база уязвима» с высоким приоритетом, действующих для каждого командира. Вариант defend_1 входит в finalStates и завершает FSM после выдачи задачи. Старый распределитель NeroAI также мог забрать все 2–3 группы в оборону из-за округления 70% вверх. Семантика завершения finalStates описана в [официальной документации FSM](https://community.bistudio.com/wiki/FSM).

### Цепочка секторов

`wlGraph` строит цепочку только через принадлежащие стороне сектора от её базы. Отдельно возвращаются все свои сектора, связные свои сектора и доступные соседние чужие сектора. Изолированный свой карман остаётся своим, но не снабжает продвижение глубже.

Доступность захвата проверяется непосредственно нативным триггером. Сектор должен одновременно быть доступен по цепочке и быть текущей целью либо ранее своим сектором, который разрешено отбить. История завоеваний не обходит разрыв цепи. После нативной смены владельца кэш топологии сбрасывается, включая изменения в пределах одного simulation frame. Общий кэш разделяется между триггерами; полный поиск не выполняется независимо для каждого бойца.

Независимый серверный наблюдатель раз в секунду проверяет активные цели. Потеря последнего пути вызывает штатный сброс выбора конкретной стороны, очищает её голоса/таймер голосования/показатель захвата и останавливает прежние автономные задачи NeroAI. Прямое движение/удержание игрока не отменяется, но недопустимый захват не продолжается. Native FSM получает обычный BIS_WL_sectorVotingReset; fallback для стороннего FSM убирает зависшую цель через 3 секунды. Цель, уже захваченную своей стороной, обрабатывает штатное завершение. Другая сторона продолжает свою допустимую задачу.

Если существует альтернативная связная цепочка от базы, цель сохраняется. Простого соседства захваченной точки недостаточно для отмены: проверяется именно потеря доступности.

### Осада базы

В тактическом режиме NeroAI при доступном ранее потерянном подходе к базе распределитель оставляет минимум одну пригодную пехотную группу для контратаки и минимум одну доступную группу для обороны. Кандидат выбирается по расстоянию к потерянной точке и боеспособности. Прямые команды игрока, ремонт, доставка и активная поддержка исключаются из доступных сил. Единственная доступная группа остаётся в обороне; истощённые остатки не становятся символической атакующей группой.

Контратака получает конкретный ранее свой сектор, связанный с базой и доступный по цепочке. Приоритет — последний потерянный подход, иначе ближайший допустимый. Пехота/техника используют этот проверенный объект как задачу вместо старой дальней цели. Это использует штатную возможность отбивать ранее свои точки, не меняет владение секторами и не заставляет голос игрока выбирать другую цель. Штурм всё ещё требует готовности и координации из этапа 1. Под осадой единственную контратакующую группу не забирают в закрепление другого сектора или новую авиационную роль.

Штатным не подключённым к NeroAI командирам, в том числе стандартному режиму, добавлено аналогичное ограничение обороны через общий распределитель. Их оборонная задача пересматривается, а defend_1 перестал быть финальным состоянием. Авиация/пехота сохраняют остальную штатную логику закупки, голосования и fast travel.

Для подключённых к NeroAI групп штатный FSM переходит в состояние ожидания управления: не телепортирует их на базу, не создаёт встречные маршруты и не включает штатное уничтожение «застрявшего» неподвижного бойца. Закупочный FSM остаётся отдельным. После снятия NeroAI штатное управление возобновляется. В LLM-режиме поддерживается штатное голосование; ручной/тактический контроллер движения не подменяется. Распределение координированной контратаки подключённых групп относится к тактическому режиму; отдельный LLM планировщик сохраняет своё управление.

В точке передачи управления удаляются только два штатных waypoint, записанные нашим адаптером WLAIPathSegmentation. Произвольные waypoint миссии не выбираются для удаления. Генераторы адаптеров находятся в `tools/adapt-frontline.js`; исходные нативные файлы в `research/native/Warlords` сохранены из установленного PBO. Последующие изменения должны делаться в генераторе.

Область этой правки — нативный двухсторонний Warlords WEST/EAST. Трёхсторонний CQ использует отдельную механику захвата; наблюдатель нативной цепочки там не включается. Его перенос и HC/MP остаются следующей адаптерной стадией.
