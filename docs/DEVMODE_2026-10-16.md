# DevMode — 16 October 2026

Separate tab in Control Center. Select updates, then use the existing Save All or Save and Launch action. Flags belong to the launch profile (including named presets), not the map geometry preset. They take effect on the next mission start, never mid-flight or during a repair lease.

Initial experiments: physical infantry supply flights outside bases, crew on NeroAI ground-vehicle purchases, tactical autonomous repair/cover cycle. Existing profiles retain all three to avoid silently changing their behaviour. Newly added experiments must default to false. Turning the master off retains individual choices but emits zero for each experimental runtime flag. Debug console/Zeus is a separate existing setting.

Transport off uses native parachute delivery outside bases; base ground delivery stays active. The purchase planning gate, native infantry eligibility and adapted native WLAirdrop gate all read the same flag. Vehicle crew only affects NeroAI purchases. Repair off disables vehicleBattleWatch; explicit player repair remains available. Tactical repair requires tactical mode. Custom three-side shopping retains its own delivery implementation. Antistasi stores the preferences but does not apply these Warlords features; its UI states this.

Registry: control-center/dev-mode.js. It defines ids, labels, descriptions, defaults, stage, and mission config fields. Validation rejects unknown ids and non-boolean flags. There are no arbitrary SQF expressions or executable user-supplied values. CfgNeroExperiments is generated for native and three-side missions; applySettings reads it before settingsApplied, publishes the three variables and logs [NeroWL DevMode]. Missing config in older missions preserves previous defaults.

To add an update: add an experimental entry with default:false, consume its field in mission settings/runtime with a defined fallback, and add a behavioural check. Run node tools/sync-workspace-ui.js to regenerate embedded UI. New UI entries render automatically from the registry.

To promote a tested update: keep its id for old profiles, change stage to stable, provide parameter pointing to its new ordinary boolean lobby parameter, add that parameter to params.hpp and standard help. It disappears from the experimental menu. The ordinary parameter overrides the former experimental preference; the DevMode master no longer controls it. The effective-value helper uses the saved feature preference when no ordinary value exists; migrate that preference into the standard parameter in core.validate when introducing the parameter so the visible standard control also preserves the previous choice. Do not delete old registry ids without a profile migration.

Validation: DevMode and launch tests cover legacy defaults, strict validation, master/individual selection, opt-in defaults, promotion precedence, mission configuration, real temporary three-side generation and launch settings propagation. Browser acceptance uses in-memory fixtures: save/reload flags, master retention, preset application, 1440/1280 layout and existing unified workspace workflows. Combat/logistics suites execute pure SQF decisions and parse production integration files. applySettings also parsed with SQF-VM. Live panel inspection refuses writes and captures dist/ui-review/live-devmode.json and live-devmode.png.

No Arma gameplay acceptance or installed PBO update is claimed.
